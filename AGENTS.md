# AGENTS.md

Guide for AI coding agents (Claude Code, Antigravity, Cursor, Codex, Copilot...) and for humans
working on Kaiflow or a fork of it. Read this before changing code.

Kaiflow is a local-first time tracker: a Tauri 2 shell around a Rust workspace with
a hexagonal architecture, and a React UI. It records the frontmost app and (with permission)
its window title into a local SQLite database. Nothing leaves the device except the update
check and the opt-in AI weekly review.

## Architecture map

```
crates/
  domain/            Pure rules: segments, tracking state machine, idle gaps, activities,
                     rules, privacy, goals, focus, insights. No I/O, no OS, no SQLite.
  application/       Ports (traits in ports.rs) and use cases: the engine thread
                     (engine.rs), queries, commands, export/backup, goals, focus, review.
                     Depends only on domain. Test fakes behind the `test-fakes` feature.
  adapters-sqlite/   SQLite repositories implementing application ports; forward-only
                     migrations in migrations/ registered in src/migrations.rs.
  adapters-common/   Platform-neutral adapters: sampler core, idle edges, signal fan-out,
                     files, keychain secrets.
  adapters-ai/       HTTP clients for the opt-in AI review (Anthropic, OpenAI, Gemini, Ollama).
  adapters-macos/    NSWorkspace, Accessibility (AX), idle, lock, permission.
  adapters-windows/  Win32 foreground window, WinEvent hook, idle, lock, power.
  adapters-linux/    X11 (x11rb) focus and idle, logind over D-Bus, Wayland detection.
src-tauri/           Shell: composition root (composition.rs, the only place that knows
                     concrete adapters), platform.rs (cfg-gated adapter choice), typed IPC
                     (src/ipc/), use cases on AppState (api.rs), tray, windows, updater.
src/                 React 19 + TanStack Query + Tailwind 4.
  windows/           Entry points: popover, main, onboarding (one HTML per Tauri window).
  features/<name>/   containers/ (data + state, call IPC hooks) and components/
                     (presentational, props only), plus lib/ and hooks/ when needed.
  shared/ipc/        bindings.ts (GENERATED), queries.ts (typed query/mutation hooks),
                     client.ts, queryKeys.ts, useTauriEvent.ts.
  shared/ui/         Design-system primitives.
  dev/               In-memory mock backend for `npm run dev:mock` and E2E. Never shipped.
e2e/                 Playwright specs against the mock backend, with axe accessibility checks.
website/             Astro landing page (EN + ES), isolated npm project.
docs/                Release, platform support, forking guide, checklists.
```

Dependency direction: `domain` <- `application` <- `adapters-*` <- `src-tauri`. The UI talks
to the backend only through the generated IPC bindings.

## Invariants (do not break)

1. **The domain stays pure.** `crates/domain` has no I/O, no clocks, no OS or database
   crates. Time comes in as values (`UtcMs`). Add dependencies there only if they are pure
   (like `regex`).
2. **One writer.** The engine thread in `application/src/engine.rs` owns the tracking state
   machine and the write repository. Writes go through engine commands; other code reads.
   Do not open extra write connections or write from IPC handlers directly.
3. **Every OS call is behind a port.** New OS capabilities get a trait in
   `application/src/ports.rs`, an implementation per platform adapter crate, and wiring in
   `src-tauri/src/platform.rs` / `composition.rs`. The application layer never calls the OS.
4. **Privacy.**
   - Never capture screen content, keystrokes, clipboard or file contents.
   - Window titles are optional (Accessibility on macOS) and respect the user's privacy
     rules (excluded apps, hidden titles) before they are stored (`domain::apply_privacy`).
   - **Never send data off the device**, except the opt-in AI weekly review (user enables a
     provider, previews the payload, and runs it) and the signed update check. No telemetry,
     analytics, remote fonts or CDNs in the app.
   - API keys live in the OS keychain (`adapters-common::secrets`), never in files or SQLite.
5. **Least privilege in the webview.** Windows get only the commands they need via
   `src-tauri/capabilities/*.json`. Tauri plugins are used from Rust only; no window is granted
   plugin permissions.
6. **Migrations are forward-only.** Never edit a shipped migration; add a new one.
7. **Generated files are generated.** Do not hand-edit `src/shared/ipc/bindings.ts` or
   `src-tauri/permissions/autogenerated/`.
8. **Presentational components do not fetch.** Containers call hooks from
   `@/shared/ipc`; components take props.

## Adding a feature end to end

Example: a new "tags" table with a list command shown in the main window.

1. **Migration**: add `crates/adapters-sqlite/migrations/000N_<name>.sql` and register it in
   `MIGRATIONS` (`crates/adapters-sqlite/src/migrations.rs`) with the next version.
2. **Domain**: types and pure rules in `crates/domain/src/<name>.rs`, exported from `lib.rs`,
   with unit tests (property tests with `proptest` where it fits).
3. **Application**: a port trait in `ports.rs` (repository or OS capability) and the use case
   (query, command or engine command). Test it with the fakes in `application/src/fakes`.
4. **Adapter**: implement the port (`adapters-sqlite/src/<name>_repo.rs`, or each platform
   crate) with tests against a temp database.
5. **Wiring**: construct it in `src-tauri/src/composition.rs`; expose a use case on
   `AppState` in `src-tauri/src/api.rs`.
6. **IPC command**:
   - DTOs in `src-tauri/src/ipc/dto.rs` (derive `specta::Type`).
   - The command in `src-tauri/src/ipc/commands.rs`.
   - Register it in `collect_commands!` in `src-tauri/src/ipc/mod.rs`.
   - Add its name to `COMMANDS` in `src-tauri/build.rs` (a unit test enforces the sync).
   - Grant `allow-<command-name>` (kebab-case) in the capability of each window that needs
     it: `src-tauri/capabilities/main.json`, `popover.json` and/or `onboarding.json`.
7. **Bindings**: `UPDATE_BINDINGS=1 cargo test -p kaiflow` (CI fails if
   `src/shared/ipc/bindings.ts` is stale).
8. **Query hook**: add the query or mutation in `src/shared/ipc/queries.ts` and its key in
   `queryKeys.ts`.
9. **Mock backend**: add a handler in `src/dev/mockBackend.ts` (or a `mock<Name>.ts` module
   spread into `handlers`). Unmocked commands throw `unmocked command: <name>`.
10. **UI**: `src/features/<name>/containers` + `components`, wired into the window or
    section. Use `@/shared/ui` primitives; keep both themes and keyboard access working.
11. **Tests**: Vitest next to the code (`*.test.tsx`), and a Playwright spec in `e2e/`
    (uses the mock backend, runs axe).

## Verification commands

Run all of them before you say a change is done:

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo build -p kaiflow
npx tsc --noEmit
npm run lint
npm test
npm run build
npm run e2e                       # first time: npx playwright install chromium
npm --prefix website run check    # only if website/ changed
npm --prefix website run build    # only if website/ changed
```

Avoid `tauri build` (release bundles) unless you are working on packaging: it is slow and uses
a lot of disk.

## Running the UI without Rust

```bash
npm run dev:mock
```

Opens Vite with the in-memory backend (`.env.mock` sets `VITE_MOCK_IPC=1`). Visit
`http://localhost:1420/main.html`, `/popover.html` or `/onboarding.html`. This is the fastest
loop for UI work and is what the E2E suite uses. The production build refuses to run with
`VITE_MOCK_IPC`, and CI checks the bundle has no mock code.

## Testing the end of a focus block (debug builds only)

`KAIFLOW_DEBUG_FOCUS_SECS=<n>` starts a timer at launch (raised to the one-minute minimum), so
the end alert (notification, popover end card, chime) can be watched without clicking through
the UI. It lives in `src-tauri/src/debug_focus.rs` behind `#[cfg(debug_assertions)]`: release
builds do not contain it. It writes a real session to the app's database.

```bash
pkill -f Kaiflow.app
npx tauri build --debug --bundles app   # then revert its change to the tauri-build line
KAIFLOW_DEBUG_FOCUS_SECS=20 target/debug/bundle/macos/Kaiflow.app/Contents/MacOS/kaiflow
/usr/bin/log show --last 3m --predicate 'process == "NotificationCenter" AND eventMessage CONTAINS "kaiflow"'
```

Notifications only behave like the real app from the bundle (a bare `tauri dev` binary posts as
Terminal). In the log, "displaying as banner" and "Playing notification sound" mean it rang;
"added to history" alone means macOS filed it silently (Kaiflow was the app in front).

## Verifying Linux from macOS (Docker)

The Linux adapters only compile on Linux. To check them without a Linux machine:

```bash
docker run --rm -it -v "$PWD":/work -w /work rust:1.93-bookworm bash -c '
  apt-get update &&
  apt-get install -y --no-install-recommends libwebkit2gtk-4.1-dev \
    libayatana-appindicator3-dev librsvg2-dev libxdo-dev libssl-dev pkg-config xvfb &&
  rustup component add clippy &&
  CARGO_TARGET_DIR=/tmp/target cargo clippy --workspace --all-targets -- -D warnings &&
  CARGO_TARGET_DIR=/tmp/target cargo test --workspace &&
  CARGO_TARGET_DIR=/tmp/target xvfb-run --auto-servernum cargo test -p adapters-linux -- --ignored'
```

`CARGO_TARGET_DIR` keeps Linux artifacts out of your macOS `target/`. Windows has no local
equivalent; rely on the `windows-latest` CI job.

## Gotchas

- **macOS Accessibility (TCC) is tied to the code signature.** Under `tauri dev` the grant
  goes to your terminal, and ad-hoc signed builds lose it on every rebuild. Test permissions
  with `scripts/dev-sign.sh` and a stable self-signed identity
  (`scripts/create-dev-identity.md`). Releases use the same idea (docs/release.md).
- **A linker-signed bundle never gets Accessibility.** Without a signing identity Tauri leaves
  the `.app` signed only by the linker (`codesign -dv` shows `linker-signed`, an identifier like
  `kaiflow-<hash>` and `Info.plist=not bound`). TCC cannot match that to any grant, so titles
  stay empty even when System Settings shows Kaiflow enabled. `tauri.conf.json` sets
  `signingIdentity: "-"` so every bundle is a proper ad-hoc signature; CI overrides it with
  `APPLE_SIGNING_IDENTITY`. Check with `codesign --verify --deep --strict` and the
  `accessibility trusted=` line in `diagnostics.log`.
- **`tauri build` may rewrite `src-tauri/Cargo.toml`** (the `tauri-build` features). Revert
  that hunk before committing.
- **Tauri plugins stay on the 2.x line.** Do not upgrade any `tauri-plugin-*` to 3.x alphas;
  `tauri-specta` / `specta` are pinned to exact RCs on purpose.
- **Rust >= 1.93** (edition 2024, `rust-toolchain.toml`). Node >= 22.12.
- **Command names**: snake_case in Rust and `build.rs`, kebab-case `allow-...` in
  capabilities, camelCase in `bindings.ts` (`commands.getStatus()`).
- **Window titles may be private.** Never log them, and never put real titles in fixtures,
  screenshots or issues.
